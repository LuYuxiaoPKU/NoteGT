# 03 · 音符盒发声机制（NoteBlock 全链路：25 音高 × 23/27 乐器）

> 证据：`_sources/dec12111b/efi.java`（1.21.11 NoteBlock 反编译）、`_sources/dec262/net/minecraft/world/level/block/NoteBlock.java`（26.2 官方命名）、
> `_sources/instrument-mapping-12111.txt` / `_sources/instrument-mapping-262.txt`（block→乐器映射全表）、
> `_sources/noteblock-wiki.txt`（wiki，抓取 2026-08）。
> **1.21.11 与 26.2 的 NoteBlock 逻辑逐行一致**（仅 26.2 多 4 个 TRUMPET 枚举）。

## 1. 方块状态

| 属性 | 类型 | 范围/默认 | 证据 |
|---|---|---|---|
| `INSTRUMENT` | EnumProperty<NoteBlockInstrument> | 23 常量（1.21.11）/ 27（26.2，+4 TRUMPET） | eox.bk / 26.2 BlockStateProperties.NOTEBLOCK_INSTRUMENT |
| `NOTE` | IntegerProperty | **0..24**（25 档） | `IntegerProperty.create("note", 0, 24)` [1.21.11 已验证 eox.aV + 26.2 已验证] |
| `POWERED` | BooleanProperty | 默认 false | 红石充能状态 |

- 默认状态：HARP + note=0 + 未充能。
- 破坏/放置时 NOTE 不保留（新块 note=0）[1.21.11 已验证：defaultState 即 0]。
- 方块注册：`dzs.a("note_block", efi::new, Properties...instrument(epi.e=BASS).explosionResistance(0.8f))` [1.21.11 已验证]。
- NBT/命令：`/setblock` 的 `note` 数据值 0..24 [wiki 行 816：`{bst|note|0|0,1,...,24}`]。

## 2. 触发路径（四条，全部汇聚到 blockEvent id=0）

[1.21.11 已验证：efi.java 全类 + 26.2 已验证]

1. **红石**：`neighborChanged` 中 `state.POWERED` 由 false→true（上升沿）→ `playNote(null, state, level, pos)`，并 set POWERED=true。
   - 注意：是**信号上升沿**触发（比较旧充能值），1 tick 信号（脉冲）会触发一次；**持续高电平不重复触发**。
2. **攻击**（`onAttack`/`playerWillBreak` 分支）：`playNote(player, ...)` + 统计 `STATS.BROKEN/NOTE_BLOCK`（混淆 bdk.ah）。
3. **右键（use）**：`useWithoutItem`：`NOTE = (NOTE+1) % 25`（25 次按回 0）→ set 状态 → `playNote(player,...)` + 统计（bdk.ai）。
4. **blockEvent(0,0)** 本身：`triggerEvent` 才是真正发声（见 §3）。`playNote` 只做两件事：
   ```java
   private void playNote(@Nullable Entity source, BlockState state, Level level, BlockPos pos) {
       if (state.INSTRUMENT.worksAboveNoteBlock() || level.getBlockState(pos.above()).isAir()) {
           level.blockEvent(pos, this, 0, 0);            // 客户端/服务端各自触发
           level.gameEvent(source, GameEvent.NOTE_BLOCK_PLAY, pos);   // 振动（苦力怕…不，悦灵/潜声传感器）
       }
   }
   ```
   **上方既不是空气也不是 mob head（即被任意方块压住）→ 完全静默**（不发声、无事件、无粒子）；但右键仍会改变音高。[1.21.11 已验证 + wiki 行 48]
   - `worksAboveNoteBlock()` = 乐器 type ≠ BASE_BLOCK（mob head / custom head 可以"压"在音符盒上并发声）。

## 3. triggerEvent（真正发声处，blockEvent id=0）

```java
boolean onBlockEvent(...) {                          // 1.21.11 efi.a(eoh,dwo,is,int,int) / 26.2 triggerEvent
    NoteBlockInstrument inst = state.INSTRUMENT;
    float pitch;
    if (inst.isTunable()) {                          // BASE_BLOCK 型（16 种，26.x 17 种含 trumpet）
        int note = state.NOTE;
        pitch = getPitchFromNote(note);              // = (float) Math.pow(2.0, (note - 12) / 12.0)
        // 粒子：音符粒子在 pos+(0.5, 1.2, 0.5)，红色分量 = note/24.0（粒子颜色=音高）
        level.addParticle(ParticleTypes.NOTE, x+0.5, y+1.2, z+0.5, note/24.0, 0, 0);
    } else pitch = 1.0f;                             // head/custom：pitch 固定 1.0（NOTE 属性被忽略）

    Holder<SoundEvent> event;
    if (inst.hasCustomSound()) {                     // CUSTOM_HEAD（玩家头颅）
        Identifier soundId = 上方头颅 SkullBlockEntity.getNoteBlockSound();   // 头颅 NBT "Note" 组件
        if (soundId == null) return false;
        event = Holder.direct(SoundEvent.createVariableRangeEvent(soundId)); // 任意自定义事件！
    } else event = inst.getSoundEvent();             // 枚举内置事件

    level.playSeededSound(null, x+0.5, y+0.5, z+0.5,
                          event, SoundSource.RECORDS,
                          3.0f /*=NOTE_VOLUME*/, pitch,
                          level.getRandom().nextLong());   // seed → 双端一致的文件随机
    return true;
}
```

**`getPitchFromNote(int n) = 2^((n−12)/12)`** [1.21.11 已验证 efi.b + 26.2 已验证]：
- note 0 → 0.5（F♯3），note 12 → 1.0（C4 中央 C），note 24 → 2.0（F♯5）。
- 引擎端再 clamp [0.5, 2.0]（正好覆盖，不截断）。
- 与 wiki 音高表一致（use count = note 值；wiki 表：0→0.5 … 11→0.943874 … 24→2.0）[wiki 行 71-203]。
- **各乐器的"实际音域"差异来自样本本身的基频**（bass 样本低两个八度、flute 高一个八度等），pitch 参数对所有乐器是同一个乘数。[wiki 行 54]

## 4. NOTE_VOLUME = 3 的真相（wiki"48 格"的来源）

`playSeededSound(..., volume=3.0f, pitch, seed)` 中的 3.0f：
- 客户端 `SoundInstance.volume = 3.0`（× 文件音量 1.0 = 3.0）；
- **衰减距离 = max(3.0, 1.0) × 16（文件 attenuation_distance 默认）= 48 格**；
- **增益 = clamp(3.0, 0, 1) = 1.0** × RECORDS 滑条 → 满音量；
- 服务端 `SoundEvent.getRange(3.0) = 16×3 = 48` → 48 格外的客户端根本收不到该声音包。
→ 三处自洽：**可闻半径 48 格**，与 wiki "can be heard from up to 48 blocks away" 完全吻合。[1.21.11 已验证 + 26.2 已验证 + wiki]

对照（同机制不同参数）：
| 音源 | volume 参数 | 衰减距离 | 备注 |
|---|---|---|---|
| 音符盒 | 3.0f | 48 | RECORDS |
| 唱机 forJukeboxSong | 4.0f | 64 | RECORDS [26.2 已验证] |
| 普通 playSound 默认 | 1.0f | 16 | — |
| 环境 mood | 1.0f | 16 | AMBIENT LINEAR |
| 山羊角（instrument 数据） | range 256.0 | — | 走 item instrument 定义（`data/minecraft/instrument/*.json` 的 `range` 字段，26.2 已验证） |

## 6. 头部（mob head / 玩家头颅）

[1.21.11 已验证 + wiki]
- 音符盒上方放 head：乐器优先级 **上方块 > 下方块**（setInstrument 逻辑：上方 worksAbove → 用上方；否则下方（下方是 BASE_BLOCK 型则强制 HARP…实为 `instrumentBelow.worksAboveNoteBlock() ? HARP : instrumentBelow`））。
- mob head → 对应 `block.note_block.imitate.*` 事件（环境音；creeper 是 hissing×0.5pitch）；**pitch 恒 1.0，NOTE 属性无效，无音符粒子**。
- 玩家头颅 → 读头颅 `Note`（Identifier，SkullBlockEntity.getNoteBlockSound()）→ 可播**任意**音效事件（这是原版自带的"自定义声音音符盒"）；无该 NBT 时 fallback `UI_BUTTON_CLICK`（枚举常量）但实际以 getNoteBlockSound() 返回 null 则整个 playNote 返回 false（不发声）。
  - ⚠️ 细节：`getCustomSoundId` 返回 null → triggerEvent 返回 **false**（不发声）；CUSTOM_HEAD 枚举里的 UI_BUTTON_CLICK 只是注册表占位。[1.21.11 已验证 efi.a(dwo,is) 判空]

## 7. 相关系统联动

- **GameEvent NOTE_BLOCK_PLAY**：发声时发出（供潜声传感器/监听着）[1.21.11 已验证]。
- **悦灵（Allay）**：16 格内听到音符盒 → 寻路过来，30 秒内丢物品给音符盒（被羊毛隔振动则失效；player head 音符盒例外可吸引）[wiki 行 772 + 22w17a 历史]。
- **观察者**：音符盒音符变化（右键/破坏重放）会触发观察者（Java 端 block state change）[wiki 行 762]。
- **统计**：破坏发声 / 右键发声 各一个 advancement 统计 [1.21.11 已验证 bdk.ah / bdk.ai]。
- **唱片/唱机对照**：唱机 = RECORDS 4.0（64 格）、`JukeboxSongPlayer`（服务端 tick + gameEvent JUKEBOX_PLAY）→ 客户端 `forJukeboxSong`；26.2 唱片系统重构为 `JukeboxSong` 注册表 + `DataComponents.JUKEBOX_PLAYABLE` [26.2 已验证]。
- **F3**：`note: N` 显示当前音符盒 NOTE 值 [wiki 行 215]。

## 8. 给模组的关键结论

1. 音符盒每次发声 = 一个**新的 SoundInstance**（SimpleSoundInstance 形态：RECORDS/3.0f/pitch/LINEAR/方块中心+0.5）+ 一个静态通道；**没有状态延续**——1gt（20Hz）演奏 = 每秒 20 个新 voice 叠加，这是声学问题的根源（Hy4 结论 1）。
2. 要"延音/legato"，必须在**模组层合并 voice**（L1）或**替换样本做成可 loop**（L2），引擎本身不提供。
3. 替换样本走资源包（sounds.json 同名覆盖）零代码；改 volume/attenuation_distance/stream 也可纯资源包。
4. 自定义"乐器"可以：a) 资源包加 sounds.json event + 方块数据指定（需 data-pack 改 block 注册，1.21.11 起方块注册仍在代码内，**不能纯 data 加乐器映射**——instrument 是 Properties 字段 [1.21.11 已验证]）；b) 玩家头颅 NBT（免方块改动，任意事件）；c) 模组 Mixin 改 `triggerEvent` 或拦截 `playSeededSound`。
