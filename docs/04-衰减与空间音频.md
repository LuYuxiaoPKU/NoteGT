# 04 · 衰减、空间音频与「混响」真相

> 证据：`_sources/dec262/com/mojang/blaze3d/audio/Channel.java`、`Listener.java`、`Library.java`；
> `_sources/dec12111b/fwh.java`（1.21.11 Library，池计算与 HRTF 属性逐行一致）。

## 1. 距离衰减：精确公式 [Channel.java 反编译，1.21.11 与 26.2 相同]

```java
void linearAttenuation(float maxDistance) {
    alSourcef(src, AL_SOURCE_DISTANCE_MODEL, AL_LINEAR_DISTANCE /*53251, AL_EXT_LINEAR_DISTANCE 模型*/);
    alSourcef(src, AL_SOURCE_MAX_DISTANCE,  maxDistance);   // 4131
    alSourcef(src, AL_SOURCE_REFERENCE_DISTANCE, 1.0f);     // 4129
    alSourcef(src, AL_SOURCE_ROLLOFF_FACTOR, 0.0f);         // 4128
}
void disableAttenuation() {
    alSourcei(src, AL_SOURCE_DISTANCE_MODEL, AL_NONE /*0*/);
}
```

- 距离模型 = **AL_EXT_LINEAR_DISTANCE**（OpenAL Soft 扩展；Library init 时检查该扩展并 `alEnable(AL_EXT_SOURCE_DISTANCE_MODEL=512)` 允许 per-source 模型）。
- OpenAL Soft 对该扩展模型的实现：**gain = 1 − (d − ref) / (max − ref)**，clamp 到 [0,1]（该模型不使用 rolloff；rolloff=0 也印证了纯线性 1→0）。[推断：AL_EXT_LINEAR_DISTANCE 规范 + OpenAL Soft 行为；rolloff 显式置 0 已验证]
- 即音符盒（ref=1, max=48）：
  | 距离 d | 增益 |
  |---|---|
  | ≤1 格 | 1.0 |
  | 24.5 格 | 0.5 |
  | 48 格 | 0（且 48 格外服务端根本不发声音包） |
- **没有 1/d、对数、指数衰减**（1.20.4 起 Attenuation 枚举只剩 NONE / LINEAR 两个值，INVERSE/LOG_CUBED 已移除 [1.21.8 javadoc + 1.21.11 已验证 ipm$a 枚举仅 2 常量 + 26.2 已验证]）。
- `Attenuation.NONE` → 完全无衰减（UI/音乐/环境相对源）。

## 2. 3D 定位与 listener

- 源位置：`setSelfPosition(Vec3)` → `AL_SOURCE_POSITION`（音符盒 = 方块中心 +0.5）。
- 相对源：`setRelative(true)` → `AL_SOURCE_RELATIVE`（514）——源随 listener 走（UI/MUSIC/AMBIENT 相对源）。
- Listener：`Listener.setTransform(ListenerTransform(position, forward, up))`：
  ```java
  alListener3f(AL_POSITION, pos.x, pos.y, pos.z);   // 4100
  alListenerfv(AL_ORIENTATION, forward.x, forward.y, forward.z, up.x, up.y, up.z);  // 4111
  ```
  [26.1 起 Listener 重写为直接 AL 调用；1.21.11 混淆版同结构 fwi]
- **`ListenerTransform` 只有 position/forward/up —— 没有速度/加速度分量** → **无多普勒效应**（玩家跑动不会让音符盒音高变化）。[1.21.8 javadoc record 定义 + 26.2 已验证]
- Listener 每帧由渲染线程 `updateSource(camera)` 更新，取**主相机**位置（第一人称=玩家眼睛；第三人称=相机球面位置）[26.2 已验证 Minecraft 类行 1132]。

## 3. HRTF（方向性音频）

- 设置项「定向声音」（Directional Audio）→ `Library.init(device, useHrtf)`：
  context 属性 `ALC_HRTF=1`（当设备支持 `ALC_SOFT_HRTF`）+ `ALC_HRTF_MODE=0`。[1.21.11 已验证 fwh 行 120-128 + 26.2 已验证]
- 效果：双耳渲染（OpenAL Soft 内部）；不改变衰减公式、不增加任何效果器链。
- 对模组的意义：HRTF 是**设备级开关**，模组若自建 OpenAL 设备做 EFX 混响，可以顺带控制 HRTF；但**不要假设 HRTF 打开**。

## 4. 原版「混响」结论：没有混响总线

**Minecraft 客户端音频 = 一组 AL source → 设备主输出，直出。** [1.21.11 已验证 + 26.2 已验证：全库无 EFX/SLF/reverb 任何调用]

- 无 send bus、无 reverb 效果器、无辅助发送量（aux send）、无按 source 的房间/材质反射计算。
- 所谓"原版混响感"全部来自**样本自带的尾音**（如 bell/chime 的衰减尾）+ 环境音（ambient loop）。
- 因此：
  1. **样本内混响**（把 reverb 尾预混进 ogg）：零引擎改动，资源包即可；代价是所有距离/方向共享同一尾，且尾音循环点检测需先拉平（Hy4 结论）。
  2. **离散回声**（复制音符盒 + 中继器延迟触发）：纯红石，原版可行；每个回声占一个通道。
  3. **真·空间混响（OpenAL EFX）**：模组自建 device/context，`ALdefGenerator/Effect` + `ALdefSlot` + `AL_EFFECT_REVERB`（SLF 或 EFX-Compressor+Reverb），把 MC 的 source 挂到 slot；参考 **Sound Physics Remastered**（射线追踪 + OpenAL EFX）路线。
     - 成本：接管 OpenAL 设备（与 MC 的 Library 冲突 → 需 Mixin 掉 MC 的 device 初始化或自建并行 device 并在 mixer 汇流）；性能：射线追踪/反射计算每 tick。
     - 注意：MC 的 `Channel` 只暴露 source id 包装（无 raw AL 句柄访问）→ 挂 EFX 需 Access Widener 暴露 `Channel.source`（private final int）或在 executor 线程直接 `alSource*`。[推断：CFR 反编译可见字段 private final int source，1.21.11 fwg/26.2 Channel]

## 5. 通道与重采样细节（对优化模组的约束）

- 静态池（音符盒用）247 通道 [1.21.11 已验证]：20Hz 单音符盒 = 每秒 20 个 voice × 样本时长（~0.2-0.5s）→ 稳态占用约 4-10 通道；**30+ 音符盒同时 1gt 演奏即可逼近 247 上限**，超出部分直接 NOT_STARTED（丢音，无提示）。
- 样本解码后 PCM 常驻内存直到资源重载（`SoundBufferLibrary.cache` 无 LRU！）→ 替换大样本（立体声/高时长 loop）要注意内存。[1.21.11 已验证：cache Map 只增不减，reload 时 clear]
- 重采样：解码保留原率（44.1k/48k），OpenAL Soft 播放时转设备率（通常 48k）——**pitch 变化由 AL_SOURCE_PITCH 实现（变调+变速）**，音符盒 pitch 0.5..2.0 即半音平移的代价：样本里的噪声/泛音一起变调。[Channel.setPitch → AL_SOURCE_PITCH 4099，已验证]

## 6. 采样点：模组混音的「钩子面」汇总

| 钩子 | 位置 | 能做什么 |
|---|---|---|
| 替换样本 | 资源包 sounds/ + sounds.json | 改音色/包络/loop/采样率；改 attenuation_distance、stream、volume 区间 |
| 事件重定向 | 资源包 sounds.json（type event / 同名覆盖） | 让 note_block.X 指向自定义 event |
| `SoundEventListener` | SoundManager 公开 register | 监听每次发声（instance/event/range）——做旁路分析、触发 L1 合并 |
| `setSourceGain` | SoundEngine 公开 | 动态改分类增益（做自动混音/ducking） |
| Mixin `SoundEngine.play` | 客户端 | 拦截/改写/替换 SoundInstance（合并 voice 的最佳挂点） |
| Mixin `Channel`（AW 暴露 source） | blaze3d | 直接 AL 控制（EFX 挂接、手动 gain 包络） |
| Mixin `NoteBlock.triggerEvent` / `Level.playSeededSound` | 服务端+客户端 | 改音符盒音量/pitch/事件/位置（如把 3.0f 换成可调值） |
| 自建 device | Mixin `Library.init` | 全权接管（重混音终极方案，成本最高） |
