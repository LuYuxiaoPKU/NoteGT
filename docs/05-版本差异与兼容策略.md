# 05 · 版本差异与兼容策略（1.21.8 → 1.21.11 → 26.1/26.2）

> 本项目目标「1.21.11 以上」= 下限 1.21.11，上探 26.x。本文给出**逐项**差异与对应策略。
> 全部结论均已在反编译层核对（见 07 证据清单）。

## 1. 声音引擎（SoundManager / SoundEngine / Library / Channel）

| 维度 | 1.21.8 | 1.21.11 | 26.1 | 26.2 |
|---|---|---|---|---|
| 引擎结构 | 同 | 同 | 同 | 同 |
| 通道池公式 `sqrt→[2,8] / total-[8,255]` | ✅ | ✅（fwh 行101-102） | — | ✅（Library 同式） |
| 衰减 `max(vol,1)×attDistance` | ✅ | ✅（iqo 行334） | — | ✅（SoundEngine 同式） |
| Attenuation 枚举 | NONE/LINEAR | NONE/LINEAR | — | NONE/LINEAR |
| 常量（PITCH 0.5-2.0 / VOLUME 0-1 / LIFETIME 20 / 设备检查 1000ms） | ✅ | ✅ | — | ✅ |
| **主客户端类** | Minecraft (fue) [1.21.8 mappings 已验证] | **Minecraft** (gfj) [1.21.11 mappings 已验证] | — | Minecraft（未变）[26.2 已验证] |
| **SoundInstance 位置标识方法** | getLocation()（1.21.8 javadoc） | **getIdentifier()**（返回 Identifier）[1.21.11 mappings 已验证] | — | getIdentifier() [26.2 已验证] |
| **资源定位类型** | ResourceLocation [1.21.8/1.21.9/1.21.10 mappings 已验证] | **Identifier**（1.21.11 改名）[1.21.11 mappings 已验证] | — | Identifier（未变）[26.2 已验证] |

**结论**：引擎数值/公式在 1.21.8→26.2 之间**稳定不变**；符号改名分界在 **1.21.11**（Mojang 官方改名：ResourceLocation→Identifier、getLocation()→getIdentifier()），**1.21.11 与 26.x 命名完全一致 → 我们的目标区间（1.21.11 起）无跨版本改名负担**。（更正 2026-08：此前误记「26.2 重命名 MinecraftClient→Minecraft」——`MinecraftClient` 是 YARN 名而非 Mojang 官方名；官方 1.21.8 起主类就叫 `Minecraft`。证据：`_sources/mc1218-client-mappings.txt` / `mc12111-client-mappings.txt`，piston-data 官方 client_mappings。）

## 4. 兼容策略（给模组的工程决策）

1. **以 1.21.11 为编译目标**（loader 0.19.5 / mojang mappings / Loom 1.17.x / fabric-api 0.141.x）。
2. **把「随版本变化的符号」隔离到一个适配层**：
   - 主客户端类：`MinecraftClient`(≤25.x) vs `Minecraft`(26.x) —— 若需引用，用反射/服务发现或双 Mixin target。
   - `getLocation()` vs `getIdentifier()`、`ResourceLocation` vs `Identifier`：优先**不直接引用**这些类型；必须引用时走适配接口。
   - 铜块乐器、pumpkin 乐器：若按「下方块乐器」做声学区分，**不要硬编码**，运行时读 `state.getNoteBlockInstrument()`。
3. **引擎数值/公式（池、衰减、pitch clamp、NOTE_VOLUME=3）跨版本稳定** → 可放心写死，但**每升一个大版本重跑一次反编译核对**（本项目已有 1.21.8/1.21.11/26.2 三个基线）。
4. **优先走「资源包 + SoundEventListener」的低侵入路线**（见 06），把 Mixin 深插（Channel/EFX）作为可开关的高级特性，避免绑死某版字节码。

## 6. Hy4 材料引用（3 轮讨论 + 2026-08 第二轮修正）

> 来源：`_hy4/导出区/`（对话记录、loopdetect.py、对比图）+ 2026-08 用户转发的 Hy4 侧 AI 助手答复。
> **来源性质声明**：Hy4 侧全部数字来自 **numpy 合成谐波栈数值模拟**（从未反编译源码/运行游戏/加载资源包）；
> dB 数字只在合成模型内成立，**不得当作源码级验证结果**写入验收文档。
> 源码级事实（NOTE_VOLUME=3、247+8 通道池、48 格衰减）是**我方验证**。

### 6.1 成立结论（两轮一致）

1. 1gt = **1 game tick = 50ms = 20Hz**（确认）；重触发叠加是主因（20Hz 锯齿 + 相位慢起伏）；软起音无效。
2. 「串联」必须**合并为单一 voice**：key = 乐器+音高+位置。
3. L1 合并必须配 **L2 延音**。
4. 工作顺序：**先改样本验证，再写模组**。

### 6.2 第二轮修正（2026-08，覆盖第一轮表述）

1. **撤回 −56.65 dBc**：原值用 Hilbert 瞬时幅度÷均值归一；RMS 包络复现 = **−36.2 dBc**，随机相位种子离散 ±4.8dB（−33.4~−38.2）。**不作验收线。**
2. 验收改两级：**筛选线** = 20Hz 调制 ≤ −30dBc 且包络峰峰值 ≤ 3dB（仅淘汰明显不合格）；**终审** = 对 naive 基线强制选择盲测 A/B，报告检出率。
   低频乐器 20Hz 调制**不可测**（46Hz 基频 → 窗 ≥1 周期 → 包络采样率 ≈46Hz 卡 20Hz 奈奎斯特边缘，2 次谐波混叠）→ 改看**逐周期起伏**。
3. **60ms+8ms 不通用**（185Hz 调的）。分音域参数表：

   | 音域 | 乐器 | L0 平台 | 淡化 | 路径 |
   |---|---|---|---|---|
   | F#5+ | bells/chimes/xylophone | 55 ms | ~1 周期（≈1.4ms） | L0 |
   | F#4 | flute/cowbell | 55 ms | ~1 周期（≈2.7ms） | L0 |
   | F#3 | harp/pling | **60 ms** | **8 ms sin²** | L0（验证 1.93 dB） |
   | F#2 | guitar | — | — | **L1+L2** |
   | F#1 | bass/didgeridoo | — | — | **L1+L2**（L0 反而更差：13.75 vs 原始 10.82 dB） |

   高频区补充观察（数据点少，待我方复验）：~1 个周期的淡化优于固定 8ms（370Hz：54ms+2.7ms → 1.96dB 优于 60ms+8ms → 4.07dB）。
4. **W 配置自洽对**（纠正第一轮「W 默认 2gt + 60ms 平台」的矛盾）：HOLD 时长由 W 单独决定；样本有效长度 ≥ W。
   - 纯 L0：W=1gt(50ms) + 60ms 平台，并发层 1.2。
   - 有 L2：W=2gt(100ms) + loop，并发层 1。
5. **L1 位置 key 的坑**：一个持续音必须来自**同一音符盒**；多方块拼持续音的乐谱 L1 直接失效。
   → 待做：统计真实乐谱中「同乐器+同音高+相邻 1gt 来自同一坐标」的比例。
6. L2 **优先循环点**（无限延音、内存仅一个 loop 段）；预渲染兜底 **4s**（非 8s），且**预渲染后仍打循环点**（attack+N×loop，attack 只播一次）。48k/16bit 单声道 = 96KB/s。
7. **撤销 ×(48000/44100) 换算**：新版 `loopdetect.py` 按文件原生率分析（44.1k 硬编码是缺陷，已修）；正确做法 = 对最终要加载的缓冲做检测。不统一重采样（AL_PITCH 本就在重采样）。
8. 26.1 TRUMPET×4：Hy4 侧无可靠知识、未覆盖；程序性结论 = 直接对 note/trumpet*.ogg 跑 loopdetect（强非谐性有被拒风险）→ **实测 4/4 全拒**（见 `_sources/loopdetect-run/REPORT.md`）。
9. 48 格网络截断不影响 Hy4 结论（他从未做距离测量）；听感测试布点 ≤48 格。
10. **L0 的额外价值**：并发占用降约 1/4（250ms 尾 @1gt = 5 存活 source → 60ms 平台 = 1.2）→ 直接降低 247 槽丢音率，值得单独测丢音率。
