# 01 · 声音引擎架构（SoundManager → SoundEngine → OpenAL）

> 证据：`_sources/dec262/`（26.2 命名类 CFR 反编译）、`_sources/dec12111b/`（1.21.11 混淆类）。
> 两版已逐行对照：**引擎结构在 1.21.11 与 26.2 完全同构**（仅类/方法名与少量字段差异）。

## 1. 类图（客户端）

```
Minecraft (26.2) / MinecraftClient (1.21.11)
   │  每 tick:  soundManager.tick(paused)          [游戏线程]
   │  每帧:    soundManager.updateSource(camera)   [渲染线程]
   ▼
SoundManager  extends SimplePreparableReloadListener<Preparations>
   ├─ registry: Map<ResourceLocation|Identifier, WeighedSoundEvents>   // 音效事件表（sounds.json 解析结果）
   ├─ soundCache: Map<..., Resource>                               // 全部 .ogg 文件句柄缓存
   └─ SoundEngine
        ├─ library: com.mojang.blaze3d.audio.Library               // OpenAL device+context+通道池
        ├─ listener: Library.Listener                              // AL listener（相机位姿）
        ├─ soundBuffers: SoundBufferLibrary                        // ogg 解码/缓冲缓存（JOrbis 纯 Java Vorbis）
        ├─ executor: SoundEngineExecutor (单线程)                   // 所有 OpenAL 调用都排到它
        ├─ channelAccess: ChannelAccess                            // 通道句柄池管理
        ├─ instanceToChannel: Map<SoundInstance, ChannelHandle>    // 当前播放实例→通道
        ├─ instanceBySource: Multimap<SoundSource, SoundInstance>  // 按分类索引（stopAllExcept 用）
        ├─ 延迟/循环调度: queuedSounds, tickingSounds(TickableSoundInstance),
        │                 soundDeleteTime: Map<SoundInstance,Integer>
        └─ SoundEventListener 列表（字幕等旁路钩子）
```

### 关键常量 [1.21.11 已验证 + 26.2 已验证]

| 常量 | 值 | 位置 | 含义 |
|---|---|---|---|
| PITCH_MIN / PITCH_MAX | 0.5f / 2.0f | SoundEngine | 所有声音 pitch 硬 clamp 区间 |
| VOLUME_MIN / VOLUME_MAX | 0.0f / 1.0f | SoundEngine | 实例音量 clamp（注意：**衰减距离用的 volume 不 clamp**） |
| MIN_SOURCE_LIFETIME | 20 tick | SoundEngine | 停止后通道保留 20 tick 再回收（防竞态） |
| DEFAULT_DEVICE_CHECK_INTERVAL_MS | 1000L | SoundEngine | 每秒检测设备是否被拔出 |
| MISSING_SOUND | `"FOR THE DEBUG!"` | SoundEngine | 缺失音效的占位 event 副标题 |
| DEFAULT_CHANNEL_COUNT | 30 | Library | 查不到设备 source 上限时的 fallback |
| BUFFER_DURATION_SECONDS / QUEUED_BUFFER_COUNT | 1s / 4 块 | Channel | 流式（stream）音频缓冲：每块 1 秒、预灌 4 块 |
| NOTE_VOLUME | 3 | NoteBlock | 音符盒播放音量参数（见 03 文档，实际是衰减距离乘数） |

## 2. 线程模型（模组必须遵守的规矩）

[26.2 已验证，1.21.11 同构]

1. **游戏线程**：`soundManager.tick(paused)` → `SoundEngine.tick()`：
   - 每秒检查一次 OpenAL 设备变化 → 变化则 `reload`（重建 context + 重放当前声音）。
   - 非暂停时：播放 `queuedTickableSounds` 里到点的 `TickableSoundInstance`；
   - 更新 tickingSounds 的音量/pitch/位置（每 tick 调 `getVolume()/getPitch()/getX()...`）；
   - 清理 `soundDeleteTime` 到期的通道（停止 + 延迟 20 tick 释放）。
2. **渲染线程**：`updateSource(camera)` → 构造 `ListenerTransform(position, forward, up)` 交给 executor。
   - **listener 取的是主相机位置（不是玩家眼睛偏移后的 head 位置）** [26.2 已验证]。
3. **SoundEngineExecutor（专用单线程）**：所有 `Channel` 的 OpenAL 调用（play/stop/setVolume/setPitch/attachBuffer/...）全部 `executor.execute(...)` 排队。
   - `play()` 中 `channelAccess.createHandle(pool)` 返回 `CompletableFuture<ChannelHandle>`，**`.join()` 阻塞等待**（在游戏线程上等 executor 分配通道）。
   - 缓冲加载（ogg 解码）在 `Util.nonCriticalIoPool()`（IO 池）异步进行。
4. 结论：**模组里对 SoundEngine 的读写要么走其公开方法（内部已排队），要么自己 executor 排队；不要在游戏线程直接碰 AL。**

## 3. 通道池与并发上限 [1.21.11 已验证 + 26.2 已验证，逐行核对]

`Library.init()`:
```java
int total = getChannelCount();              // 读设备属性 ALC_MAX.sources(4112)；失败则 30
int streaming = clamp((int) round(sqrt(total)), 2, 8);   // 流式通道数
int staticC  = clamp(total - streaming, 8, 255);         // 静态通道数
```
- 典型 Windows + OpenAL Soft：`ALC_MAX.sources = 255` → **static=247，streaming=8，合计 255**。
  与 wiki 记载的「255 并发（247 普通 + 8 保留）」数字吻合 [wiki，抓取 2026-08]。
- 两个池各是一个 `CountingChannelPool`：**`acquire()` 满了直接返回 null，没有抢占/steal** → 新声音拿不到通道 = `PlayResult.NOT_STARTED`（音符盒重触发叠满时直接丢音）。
- 池的占用计数 = 当前持有的 Channel 句柄数；通道自然播完（`stopped()`）后在下一 tick 的 `scheduleTick()` 里 `release()`。
- F3 调试串：`Library.f()` = `"Sounds: %d/%d + %d/%d"`（静态 used/max + 流式 used/max）。[1.21.11 已验证：fwh.f()]

## 4. `play(SoundInstance)` 全链路（26.2 源码逐行，1.21.11 同构）

```java
public PlayResult play(SoundInstance instance) {
    if (!loaded) return NOT_STARTED;
    if (!instance.canPlaySound()) return NOT_STARTED;                 // 实例可否播（默认 true）
    WeighedSoundEvents event = instance.resolve(soundManager);       // 事件→加权声音表（未知→警告一次）
    if (event == null) { warnOnce; if (!debug) return NOT_STARTED; else event = 占位"FOR THE DEBUG!"; }
    Sound sound = instance.getSound();
    if (sound == EMPTY_SOUND) return NOT_STARTED;                    // "minecraft:empty"
    if (sound == INTENTIONALLY_EMPTY_SOUND) return NOT_STARTED;      // "minecraft:intentionally_empty"（静默占位）

    float instanceVolume = instance.getVolume();                     // = 实例音量 × sounds.json 文件音量(采样)
    float attenuationDistance = Math.max(instanceVolume, 1.0f) * sound.getAttenuationDistance();
    //  ★ 衰减距离 = max(volume,1) × 文件 attenuation_distance（默认16）——音符盒 3×16=48 的来源
    float volume = calculateVolume(instanceVolume, source);          // clamp(vol,0,1) × 分类滑条 × 分类增益
    float pitch  = calculatePitch(instance);                         // clamp(pitch, 0.5, 2.0)

    if (volume == 0 && !(instance.canStartSilent() || source == MUSIC)) return NOT_STARTED;

    for (SoundEventListener l : listeners)                            // 旁路钩子（字幕等）
        l.onPlaySound(instance, event, range = isRelative||NONE ? +∞ : attenuationDistance);

    Pool pool = sound.shouldStream() ? STREAMING : STATIC;
    ChannelHandle h = channelAccess.createHandle(pool).join();       // 拿不到 → NOT_STARTED（无抢占）
    soundDeleteTime.put(instance, tickCount + 20);
    instanceToChannel.put(instance, h);  instanceBySource.put(source, instance);

    h.execute(ch -> {                                                 // 排队到 executor
        ch.setPitch(pitch);
        ch.setVolume(volume);
        if (instance.getAttenuation() == LINEAR) ch.linearAttenuation(attenuationDistance);
        else                                      ch.disableAttenuation();
        ch.setLooping(instance.isLooping() && !sound.shouldStream()); // 流式由 LoopingAudioStream 循环
        ch.setSelfPosition(new Vec3(x, y, z));
        ch.setRelative(instance.isRelative());
    });
    if (!sound.shouldStream())
        soundBuffers.getCompleteBuffer(sound.getPath())
                    .thenAccept(b -> h.execute(ch -> { ch.attachStaticBuffer(b); ch.play(); }));
    else
        soundBuffers.getStream(sound.getPath(), instance.isLooping())
                    .thenAccept(s -> h.execute(ch -> { ch.attachBufferStream(s); ch.play(); }));
    if (instance instanceof TickableSoundInstance) tickingSounds.add(instance);
    return volume == 0 ? STARTED_SILENTLY : STARTED;
}
```

要点：
- **音量双重含义**：同一个 `volume` 参数既是增益（clamp 到 0..1 后乘分类滑条），又参与衰减距离（`max(v,1)×16`）。这是现代引擎（1.20.5+ 起）取代旧 `int attenuationDistance` 参数的设计。[1.21.11 已验证 + 26.2 已验证]
- `calculateVolume = clamp(instanceVol,0,1) × clamp(options.getFinalSoundSourceVolume(source),0,1) × gainBySource(source)`；`gainBySource` 是 `Object2FloatMap` 默认 1.0（可被 setSourceGain 调整，字幕/静音逻辑用）。
- `resolve()` 在实例侧做**加权随机选文件**：`WeighedSoundEvents.getSound(random)` 按 weight 抽样（1.21.11 混淆名 `iqt.a(bgr)`；26.2 同名）。
- 停止逻辑：`stop(instance)` → 排 executor stop + 记录 `soundDeleteTime = tick+20`；`stop(source)` 按 Multimap 批量；`stopAll()` 全清 + `channelAccess.clear()`。
- 循环音：`isLooping() && !streaming` 才设 AL_SOURCE_LOOPING；流式循环靠 `LoopingAudioStream`（读到头自动 seek 0 的包装器）。[26.2 已验证：SoundBufferLibrary.getStream]

## 5. sounds.json 重载管线（资源包）

`SoundManager` 是 `SimplePreparableReloadListener`：
- `prepare(ResourceManager, Profiler)`:
  1. 收集**全部命名空间**下 `sounds.json`（资源包顺序，后包覆盖前包条目）；
  2. 用 Gson 解析为 `Map<String, SoundEventRegistration>`（FILE 型 / SOUND_EVENT 型 / 带 replace 标志）；
  3. FILE 型：校验文件存在于 `soundCache`（启动时按 `sounds/**.ogg` 列举）；volume/pitch 解析为 `SampledFloat`（支持数值或 `[min,max]` 区间）；
  4. SOUND_EVENT 型（`"type":"event"`，如 note_block.imitate.*）：指向另一个事件，**播放时把外层 volume/pitch 乘到目标事件采样上**（MultipliedFloats）——所以 creeper 头 = 苦力怕 hissing × 0.5 pitch。
  5. `isReplace()` 决定整表替换还是合并 addSound。
- `apply(registry, soundCache, engine)`: 清表、putAll、`preloadIfRequired`（`"preload":true` 的文件立刻异步解码）、`soundEngine.reload()`。
- 缺失 event：`SoundEngine.a()`（26.2: `init()` 内）遍历内置 `SoundEvents`（`mi.b`）逐个查表，缺失打 warn（每 event 只 warn 一次，`ONLY_WARN_ONCE`）。

详见 02 文档的字段全表。

## 6. 设备/HRTF 细节 [1.21.11 已验证 + 26.2 已验证]

- 设备选择：`OpenAlUtil` + `alcOpenDevice(首选设备 ? : 默认设备)`；`CallbackDeviceTracker`（SOFT_system_events）或 `PollingDeviceTracker` 监听热插拔。
- Context 属性：`ALC_HRTF`(6546)=`useHrtf && 设备支持 ALC_SOFT_HRTF`、`ALC_HRTF_MODE`(6550)=0、`ALC_ATTRIBUTES_SIZE`(6554)=1。
  - 「定向声音」（方向性音频）选项 = HRTF；**listener 仍无速度分量（见 04 文档，无多普勒）**。
- 每个 Channel 创建时 `alEnable(AL_EXT_SOURCE_DISTANCE_MODEL=512)`（per-source 距离模型），并检查 `AL_EXT_LINEAR_DISTANCE` 扩展。
- OpenAL 绑定 = LWJGL `org.lwjgl.openal`（原生库随客户端 jar 分发；Windows 上是 OpenAL Soft）。
- `SoundBuffer`：`alGenBuffer` + `alBufferData`（PCM，格式来自 JOrbis 解码：`AudioFormat` 采样率/位深/声道保留原文件）。
