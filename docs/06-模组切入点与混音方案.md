# 06 · 模组切入点与混音方案（Fabric，1.21.11+）

> 依据 01-05 的验证结论 + Hy4 讨论结论（AGENTS.md 第三节）。
> 目标：消除 1gt 重触发叠加失真（−19.56dBc → 目标 ≤ −50dBc 量级），实现 legato/延音与可控「混响感」。

## 1. 问题重述（机制层）

- 音符盒每个触发 = 新 SoundInstance + 新静态通道，**无状态延续**。
- 1gt（20Hz）同音重触发 → 20 个 voice 在 ~样本时长内叠加：幅度锯齿（20Hz）+ 相位步进（样本起始相位固定 → 5Hz 慢起伏）→ 互调失真 −19.56dBc。[Hy4 结论 1]
- 引擎层没有 voice 合并、没有延音、没有混响总线（01/04 已证）。
→ 优化必须发生在 **SoundInstance 产生之前/之时**（合并、替换、重调度）或 **样本层**。

## 2. 三层方案（按 Hy4 结论排序，先样本后模组）

### L0 · 样本整形（资源包，零代码）【第一步验证】
- **分音域包络参数（Hy4 第二轮修正：60ms+8ms 只在 185Hz 有效，不通用）**：

  | 音域 | 乐器 | 平台 | 淡化 | 路径 |
  |---|---|---|---|---|
  | F#5+ | bells/chimes/xylophone | 55 ms | ~1 周期（≈1.4ms） | L0 |
  | F#4 | flute/cowbell | 55 ms | ~1 周期（≈2.7ms） | L0 |
  | F#3 | harp/pling | 60 ms | 8 ms sin² | L0（验证 1.93 dB） |
  | F#2 | guitar | — | — | **L1+L2**（⚠️ 首验实测：用户 guitar 样本 60ms 过线 3.43pp/−38.7dBc，音域表降级为初值） |
  | F#1 | bass/didgeridoo | — | — | **L1+L2**（L0 反而更差 13.75 vs 10.82 dB） |

- **首验已完成 + 第三轮修正已吸收（2026-08，docs/09 §11）**：harp 1.95pp/−36.8dBc ≈ 模型 1.93dB（管线确认）；60ms 全局最优；逐样本定参（oxidized=75ms、guitar 60ms 过线）；**打击乐改 48ms+4ms 零重叠截尾、不压平（不做平台整形）**；铜管纯 L0；icechime 换回原版；**L0 平台段 = L2 的 attack 段（资源包只建一份，见下）**。整形产出在 `_sources/loopdetect-run/shaped-user/`（已按新规格重生成）。
- 同时可把**短混响尾**预混进样本尾（样本内混响路线，04 文档 §4.1）。
- **L0 的隐藏价值（Hy4 补充）**：并发占用降约 1/4（250ms 尾 @1gt = 5 存活 source → 60ms 平台 = 1.2）→ 直接降低 247 槽丢音率；值得单独测丢音率。
- 采样率：**不做换算**（新版 loopdetect 原生率自适应）；也不统一重采样（AL_PITCH 本就在重采样，混合率无额外成本）。

### L1 · voice 合并（模组核心，Mixin `SoundEngine.play`）
把「同一音符盒、同音高、短间隔内的重触发」**合并成一个持续 voice**：
- 挂点：`SoundEngine.play(SoundInstance)`（客户端 Mixin，@Inject 前置）：
  - 识别音符盒来源 instance：`identifier` 以 `block.note_block.` 开头 + `source==RECORDS` + `volume==3.0f`（+ 位置在方块中心）。
  - key = (乐器, 音高/NOTE, 方块位置)；**⚠️ 位置 key 意味着一个持续音必须来自同一音符盒**——多方块拼持续音（分层/加厚）的乐谱 L1 直接失效。
    → **已统计（docs/09 §7）**：.nbs 格式 = Open NBS v5（pynbs 库解析）；不存坐标，物理盒由 (layer, instrument) 唯一确定。20 个去重乐谱：快板型 1gt 同盒率 14-51%（Tetoris 47% 音符可 L1 合并、Touhou9 最长 run 96gt）；用户自创和弦型 <2.2%（L1 收益低，L2 场景为主）。
  - **W 统一 2gt + release-cancel（Hy4 第三轮，取代旧「纯 L0 W=1gt」——旧对与 60ms 平台有 40ms 静音空隙，Hy4 自认内部矛盾）**：HOLD 到 1gt 时开始淡出（RELEASE），**若淡出期间来了匹配音符 → 取消淡出、回到 HOLD**（短音仍 50ms + 拿到 2gt 合并窗口，无静音空隙）。⚠️ 取消淡出瞬间的电平跳变需 A/B 验证可接受性。打击乐不参与合并（L1 关闭）。
  - 命中已有活跃 voice → **不新建通道**，改走合并路径：
    - 方案 a（样本侧）：向现有 voice 的自定义 AudioStream 写入下一段（无跳变续播）；
    - 方案 b（包络侧）：维持现有 voice 增益包络刷新（HOLD），到期释放（RELEASE）；
  - 未命中 → 正常播放，并登记为该 key 的活跃 voice（IDLE→HOLD 状态机）。
- 状态机：`IDLE →(触发) HOLD →(1gt 到) RELEASING(淡出) →(淡出完) RELEASE；RELEASING 期间来匹配音符 →(取消淡出) 回 HOLD`（W=2gt 合并窗口 + release-cancel，Hy4 第三轮）。
- 关键约束：
  - 合并窗口内**位置/音高变化必须破合并**（音高不同 = 不同 key；位置不同 = 不同音符盒）。
  - 合并后仍要正确走 `instanceToChannel` 生命周期（停止/重载/设备切换）→ 推荐：合并 voice 用一个**长寿命自定义 SoundInstance**（实现 `TickableSoundInstance` 按 tick 刷新状态），被合并的原始 instance 直接吞掉（return 取消注入）。
  - 线程：判断在 Game 线程（play 调用处）做；通道操作仍走 SoundEngine 现有 executor（不要自己碰 AL）。
- 通道预算收益：1gt 单盒 20 voice/s → 1 活跃 voice；30 盒并发从 ~600 voice/s 的流降到 ≤30 活跃。

### L2 · 延音（sustain/loop）
- **L0/L2 统一（Hy4 第三轮）**：L0 的平台段**就是** L2 的 attack 段——资源包只建一份（attack=扫描定参的平台样本，loop=loopdetect v2 输出）。短音 = attack+release（不进循环）；长音 = attack→淡化→loop→release。
- **推荐：独立 loop 文件**——每个乐器/音高替换为 `attack + loop 段` 的流式声音（`"stream": true`）：
  - sounds.json 改 `stream: true` → 走 STREAMING 池（8 通道！）→ **注意**：延音 voice 会挤占 8 个流式槽位；
  - 或保持静态池：把「attack+loop」做成**一个长 ogg**（loop 段重复 N 遍，N 覆盖最大延音时长），`AL_SOURCE_LOOPING` 由引擎对静态缓冲自动循环（`isLooping()` 自定义 SoundInstance 返回 true）→ 占 1 静态通道，**推荐此法**。
- **延音上限（Hy4 第二轮修正）**：有循环点时**不需要上限**（loop 无限，内存只占一个 loop 段）；预渲染兜底 **4s**（非 8s），且**预渲染后仍打循环点**（attack+N×loop，循环区间设在 loop 区，attack 只播一次、尾部无限循环，一份缓冲两全）。
- **备选：`ALC_SOFT_loop_points`**（OpenAL Soft 扩展，loop start/end 样本点）——需自建 buffer 或 AW 拿到 source 后 `alSourcei(ALC_LOOP_POINTS)`；新版 `loopdetect.py`（原生采样率自适应）已对真实样本产出 attackEnd/loopStart/loopEnd，**不做 48k 换算**。
- 循环点要求：loop 段首尾相位/幅度连续（L2b 自动检测，见下）；样本尾的混响尾在循环前**拉平**（否则循环点出现周期性混响泵感）。[Hy4 结论 4 + 04 §4]
- **真实样本首测结果（2026-08，`_sources/loopdetect-run/REPORT.md` + v2 重跑 `result-v2-*.json`）**：用户库 21 个 → PASS 7 / WARN 1 / FAIL 2（didgeridoo −23dBc、icechime −16.3dBc）/ 拒 11；原版 16 个 → PASS 7 / WARN 1 / FAIL 1（icechime）/ 拒 7。
- **铜管（trumpet×4）= 纯 L0（Hy4 第三轮拍板，docs/09 §11.2）**：放宽重试（NCC 0.90 + 40ms 淡化）仍 8/8 全拒；否决 60-80ms 短循环（12-16Hz 循环率嗡鸣可闻）；仅 >1s 持续铜管音用颗粒式伪循环。
- **v2 重跑差异（新 f0 下限 30Hz + 阈值 2.0）**：guitar 仍拒（循环<80ms，放宽 0.90 才 PASS）；flute ncc 0.9996；iron_xylophone 原版升 PASS（ncc 0.9789）；原版 banjo 降为拒（循环<80ms）。打击乐（bd/hat/snare/click）f0 估计失败是预期（无可延音段，已改 L0 截尾规格不走 L2）。

### L2b · 自动循环点检测（离线工具）
- `loopdetect.py` **v5**（Hy4 第六轮 2026-08，SHA `06c2cdb5…` 23602B，存 `_sources/loopdetect-run/loopdetect.py`；历史留底 v1/v2/`loopdetect-v3port-2026-08.py`/`loopdetect-v4-2026-08.py`）：f0 估计（**下限 30Hz**）+ 子谐波纠正（`f0Source`）+ 包络拉平 + NCC≥0.95 搜索（`--span-cycles` 可调，默认 ±半周期；5ms 交叉淡化接缝，keep-best `sm<best_sm−0.05`）+ render 越界修复 + 0.5/1.0/2.0 倍音高验证；**按文件原生采样率分析**（v5 起 JSON 带 `sr` 字段）。
- **v5 判据换血（第六轮，取代 v4 三件套）**：Hy4 注入对照证实 **perr 在长 loop 上测的是 f0 精度不是接缝**（噪声底 = 360·k·ε，k=280 时 ε=0.01% 即 10°）：
  - **`seamErrDeg`**（`seam_err_cycles` 互相关分数延迟直接量测接缝错位，对 f0 误差免疫）：**≤10 PASS / 10–25 WARN_SEAM / >25 FAIL**（门限未经听感验证，A/B 终审）。
  - `periodErrDeg` 降 **advisory**（JSON 保留，不进 verdict）；`fadeNcc` 降参考（窗口相关，**不得用于刷分**：δ=0.02 时 1ms→0.984 / 5ms→0.949）。
  - `fadeDipDb` <−1.0 FAIL、120ms 门（循环率 ≤8.3Hz）、ripple/mod <2.0dB 且 <−40dBc（≥4.0dB FAIL）维持。
  - 新字段 `fadeTrace`（淡化升级逐候选轨迹：xfadeMs/seamRatio/used）、`diagWindowSamples`（诊断窗 ≥4ms）；`--span-cycles`（k·ε>0.5 时真循环点出范围 → 试 1.0/1.5）。
  - 已知小疵：`_verdict` return 后死代码（不可达，无行为影响，第七轮已提）。
- **v5 全库结果（2026-08，`result-v5-*.json`，详见 docs/09 §11.9）：41 文件 = 11 PASS / 2 WARN_SEAM / 6 FAIL / 22 REJECT**——v4 的长 loop f0 假象全部消失（bit-user 65.98°→seam 4.15、harp2-van 21.24°→1.70、iron_xylophone-van 25.81°→7.66、flute-user 95.86°→0.81 等成片转正；bassattack-van 边缘 10.58°→4.82 转正）。**PASS 11**：user bit/bell/banjo/flute/pling + van12111 bit/bell/bassattack/harp2/iron_xylophone/pling。**WARN_SEAM 2**：harp-user 11.36°、dbass-user 11.10°（A/B 待听）。**FAIL 6**：didgeridoo-user（mod −23，衰减段入窗，路线 A/B 待裁）、icechime-user（mod −16.3，已知问题轨）、didgeridoo-van（108.9ms<120）、flute-van（**seam 38.21° 真接缝问题** + lp 4.52）、icechime-van（lp 4.71）、iron_xylophone-user（86.6ms<120）。**REJECT 22**：打击乐×6/cow_bell×2/trumpet×8/短循环·非谐（与 v3/v4 一致）。
- **Q4（v3/v4 差异）已定位（第六轮，docs/09 §11.9.5）**：guitar 原生 44.1k（`sr=44100`，无 SR 泄漏）；`--xfade 0.040` 精确复现 v3 数字（1.5/−54.57）→ 真因 = v3 keep-best 无条件保留最后候选（40ms）vs v4/v5 keep-best 保留 5ms。真实样本上长 xfade 方向与合成预测相反（40ms：seam 4.88°→1.73°、lp 2.49→1.50 变好，mod −58.14→−54.57 变差）。
- **guitar(用户)@0.90**：seam 4.88° PASS，但 Hy4 按查表 12.8° 倾向不通过 → **A/B 裁决中**（12s 试听 3 版 `ab/guitar/ngs-gtr-{A=5ms,B=硬循环,C=40ms}.wav`）。
- **dbass(用户) lp 7.09 = loop 内容 ghost pluck 瞬态**（~85–95ms，30ms 包络归一后 +7.09dB，2.1Hz 周期重复；起点平移 0–15 期 pp 不变）→ 与接缝无关，裁决待第七轮（接受/换短 L/要新 take）。
- **didgeridoo(用户) 3.8s attack 真身 = 起始 breath burst 的 3.6s 衰减尾**（非 lead-in 非 swell，docs/09 §11.9.3）→ 路线 A（250ms burst+level-match）/ B（安静 200ms+10ms 淡入）待裁（试听 `ab/didgeridoo/didg-{A,B,C}.wav`）。
- 判定（verdict 字段）：PASS / WARN（ripple 2–4dB）/ **WARN_SEAM**（seam 10–25°）/ FAIL；拒因：f0 失败（打击乐）/ 非谐性过强 / 循环<80ms / 可用区过短。
- 产出：`result-*.json`（sr/attackEnd/loopStart/loopEnd + f0Source + seamErrCycles/seamErrDeg + periodErrDeg(advisory) + fadeNcc(参考) + fadeDipDb + xfadeSamples + fadeTrace + 全套指标）；样本构建脚本据此切 attack/loop 并做淡化接缝。
- **f0「二次谐波」已解决（第三轮）**：根因 = 旧 est_f0 的 60Hz 下限排除了 F#1=46.25Hz。重跑后 5 个低频样本（dbass/banjo/didgeridoo×2/bassattack）全 `f0Source=fundamental` → 基频相位翻转整体消失。

### L3 · 真·空间混响（高级可开关特性，最后做）
- 自建 OpenAL 设备 + EFX（`AL_EFFECT_REVERB`），Mixin `Library.init` 接管/桥接；音符盒 source 按「所在区块材质/房间」挂不同 reverb 参数。
- 参考 Sound Physics Remastered（射线追踪+EFX）；成本与稳定性风险最高，放最后。

## 5. 开发路线（按风险从低到高，每步独立可验证）

1. **L0 样本包**（首验完成 ✅，剩余 1-2 天）：`l0shape.py`/`verify_l0.py` 已跑通（docs/09）；剩余 = 逐样本定参落盘（oxidized 75ms 等）、Vorbis 重编码复查、整轨电平补偿、游戏内 A/B 盲测。
2. **L1 合并 MVP**（3-5 天）：Mixin play + key 状态机 + 调试 HUD（活跃 voice 数/合并命中率）；回归：普通演奏不重复/不停滞。
3. **L2 延音**（3-5 天）：静态 loop 缓冲路线（长 ogg + isLooping），配 loopdetect 自动化。
4. **L3 混响**（研究性）：EFX PoC，独立开关。
5. **26.x 兼容**：适配层 + 条件 Mixin（TRUMPET 乐器、Minecraft 类名、Identifier 类型）。

## 6. 验收标准（Hy4 第二轮修正，取代「−50dBc 量级」）

1. **筛选线**（自动，仅淘汰明显不合格）：20Hz 调制 ≤ **−30 dBc**（约 3%）**且** 包络峰峰值 ≤ 3dB。
   - 低频乐器（bass/didgeridoo，46Hz 基频）**20Hz 调制不可测**（奈奎斯特边缘混叠）→ 用**逐周期起伏**替代。
2. **终审**（人工）：对 naive 基线做**强制选择盲测 A/B**，报告**检出率**而非 dB 值。
3. 听感测试布点 ≤ **48 格**（超过 = 无声而非衰减，网络层截断）。
4. **不再使用 −56.65 dBc**（已撤回：度量口径问题 + 种子离散 ±4.8dB）。
