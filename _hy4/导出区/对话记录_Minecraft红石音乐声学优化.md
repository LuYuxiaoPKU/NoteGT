> 导出时间：2026-09-11
> 主题：音符盒音色替换后 1gt 连续播放的周期性强化问题，及自动循环点检测方案

## 第 1 轮｜红石音乐有没有混响模组

### 提问

Minecraft 红石音乐有没有混响的模组，影响声学输出？

### 回答要点

**Minecraft 里没有"给红石音乐专门加混响"的模组**，能做到的是全局环境声学模组。

**主流选择：Sound Physics Remastered**（henkelmax，Modrinth/CurseForge，约 5000 万+ 下载）
- 射线追踪实时计算环境反射，通过 OpenAL EFX 施加混响、遮挡、吸收
- 支持 Fabric / Forge / NeoForge / Quilt，1.19 起，纯客户端
- 对**所有**游戏声音生效，音符盒包含在内

**对声学输出的实际影响**
- 只改监听，不改工程；但录屏/录音时混响会被一起录进去（在音频输出链路后端）
- 性能反噬音质：音符密集时射线评估开销陡增，掉帧导致时序抖动
- 掩蔽效应：密集琶音容易糊成一团
- 可调：`reverbGain`、`attenuationFactor`、`blockAbsorption`、`airAbsorption`
- 已知冲突：Audio Improvements

**按目的选方案**

| 目的 | 建议 |
|---|---|
| 空间氛围感 | Sound Physics Remastered，压低 reverbGain |
| 纯净精准还原 | 别装，或排除音符盒 |
| 提升音质 | **Notica**（走 OpenAL，绕开 F#3–F#5 限制与坐标取整失真） |
| 延音/力度/淡入淡出 | **Extended Note Block**（velocity 0–127、sustain、毫秒级 delay） |
| 纯原版回声 | 复制音符盒 + 中继器延迟，人工离散回声 |

**核心结论**：想要录制级的混响控制，游戏里做不到。Sound Physics 给的是"你在哪个空间听"，不是"混音台上拧混响旋钮"。

## 第 2 轮｜1gt 连续播放的周期性强化

### 提问

替换 MC 音符盒某音色为弦乐短音后，前后连续播放（间隔 1gt）连接成长音，导致同一音调短音衔接处呈现周期式强化。怎么减少？

### 根因分析（模拟验证）

**定性：这是"重触发叠加"，主因不是起音瞬态**

各因素隔离测试（1gt 重触发，F#3=185 Hz）：

| 变量组合 | 20 Hz 调制深度 |
|---|---|
| 只有相位干涉（纯音·无衰减） | 基准 |
| **+ 指数衰减尾巴** | **跳到 9.5 dB 峰峰值 ← 主因** |
| + 硬起音 4ms | 9.28 dB（几乎没变） |
| + 起音噪声瞬态 | 9.20 dB（几乎没变） |

加软起音、砍弓毛噪声，实测改善 **-1.09 dB——基本无效**。

**两个机制**
1. **20 Hz 锯齿**：上一个音衰减下去、下一个音从满幅度顶起，每 50ms 重复
2. **相位步进**（慢周期）：每次重触发从相位 0 开始，185×0.05 = 9.25 周期，小数 0.25 → 每次错开 90°，每 4 个音符相位重新对齐 → **5 Hz 缓慢起伏**

### 解法（按有效性）

**★ 最优：样本改成"平台型"**

```
样本时长   = 60 ms        （1gt=50ms + 10ms 交叠）
包络       = 中间平坦，不衰减
首尾淡化   = 各 8 ms，sin²（等功率）
```

实测 **-19.56 → -56.65 dBc，改善 37 dB**

参数敏感，别调过头：

| 长度 / 淡化 | 20 Hz 调制 |
|---|---|
| 250ms 指数衰减（现状） | -19.6 dBc |
| **60ms / 8ms sin²** | **-56.7 dBc** |
| 75ms / 16ms | -29.3 dBc |
| 125ms / 30ms | -22.7 dBc |
| 55ms 快速衰减 | 起伏飙到 28 dB（留空隙，比重叠更糟） |

> **核心认知：要的是"不衰减的平台"，不是"更短的样本"。**

**★★ 更彻底：根本不重触发**
- Extended Note Block：`sustain` 参数（tick 单位）、`fade in/out`、`velocity` 0–127、毫秒级 `delay`
- NoteBlockTweaker：延音生成器，支持直线/贝塞尔/**弦乐三段包络**
- 双音色分轨：16 个乐器槽分设断奏短音与 sustain 长音

**改间隔：别改，会更糟**
- 1gt: -19.80 dBc
- 2gt: -12.81 dBc（更差 5.6 dB）
- 3gt: -11.48 dBc

**相位相干性**：`f×Δt` 越接近整数 → 完全相干 → 电平恒定（补偿即可）。高音区问题更明显。

**电平补偿**：N = 尾巴时长 ÷ 间隔，250ms@1gt → N=5，非相干 -3.5 dB，最坏相干 -14 dB，实际取 -4～-6 dB

### 操作清单

1. 压成平台包络，裁到 60ms
2. 首尾各 8ms **sin² 等功率**淡化（线性会掉 -3 dB 坑）
3. 首尾采样值接近 0，去 DC offset；.ogg 重新编码后复查（Vorbis 有 pre-skip）
4. 整轨降 3～6 dB
5. 分别试听 F#3、F#5（残余调制随音高变化很大）

## 第 3 轮｜构思"串联"模组

### 提问

能否构思一个模组，尝试将前后 1gt 播放的两个声音（方位足够接近）串联起来？

### 核心结论

**"串联"必须是"合并成一个 voice"，而不是"把两个音交叉淡化接起来"**——后者只是把 20 Hz 锯齿换了个形式。

### 一、到货即合并（零延迟）

不需要缓冲、不需要延迟：

```
t=0     音符1 → 立刻起音（零延迟）
t=50ms  音符2 匹配 → 不开新 voice，仅重置释放计时器
t=100ms 音符3 → 再重置
t=150ms 没等到 → 开始释放淡出
```

状态机：`IDLE → HOLD → RELEASE`

代价：音符尾部多拖 W（默认 2gt = 100ms）

### 二、两层必须配套

**关键耦合**：合并后只有一个 voice，若样本仍是 250ms 衰减短音，2 秒长音会在 250ms 后彻底静音。**合并消灭了锯齿，却让长音活不下来。**

| 层 | 干什么 | 依赖 |
|---|---|---|
| **L1 合并** | 消灭 20 Hz 锯齿 + 相位步进 | 无 |
| **L2 延音** | 让合并后的单 voice 持续 | 需要可循环延音样本 |

**L2 两种实现**
- **A. 独立 loop 文件（推荐）**：资源包额外提供可循环延音 .ogg，用原版整段循环
- **B. OpenAL 循环点**：`ALC_SOFT_loop_points`，衰减样本需先拉平

### 三、匹配判据

Key = **(乐器, 音高, 位置)**
- 位置：默认必须同一方块坐标，可配半径 R（0–4 格），默认 0
- 音高：差半音就是另一个音
- 间隔：窗口是 **[1, W]，不是 [0, W]**（同 tick 是和弦）

### 四、三个坑

1. **同音反复被吃掉** — MC 无力度信息，硬限制，只能靠配小 W 缓解
2. **高音区残留更明显** — 相位步进量随音高变化
3. **别用"拉大间隔"绕过** — 实测更糟

### 五、代码落点

- 拦截：`ClientPacketListener#handleSoundEvent` 或 `SoundEngine#play(SoundInstance)`
- 过滤：SoundEvent id ∈ 音符盒乐器集，category = BLOCKS/RECORDS
- 音高与乐器：优先从**客户端方块状态**读（`NoteBlock.INSTRUMENT` / `NOTE`）
- 参考 **Notica**（MIT，已有 OpenAL 直出与自定义混音器）——最佳挂载点

### 六、循环样本三条硬要求

| 要求 | 不做到 | 做到后 |
|---|---|---|
| 长度取整数周期 | 44.6× 平均样本跳变 | 13.1× |
| 拉平衰减 | 每循环掉 -4.34 dB | -0.02 dB |
| 长度 ≥ 0.3s | 听得出周期性 | 可用 |

### 七、交叉淡化增益律（反直觉：规则是反的）

| 循环段来源 | 正确增益律 | 用错的后果 |
|---|---|---|
| 相干（同一样本取循环段） | **线性 g₁+g₂=1** | 等功率 → **+3.14 dB 鼓包** |
| 非相干（独立录音） | **等功率 g₁²+g₂²=1** | 线性 → **-4.22 dB 凹陷** |

原因：相干时两路是同一波形，`cos θ + sin θ` 在中点 = √2，凭空鼓 3 dB。

### 八、可选第三层：预读模式

缓冲 2–4gt 再播，释放时机精确、能做事后包络修复。代价 100–200ms 延迟——实玩不能忍，离线录视频无所谓。

### 实测结果

合并成单一 voice：调制深度 **-19.80 → -27.32 dBc**

## 第 4 轮｜自动计算循环点的算法

### 提问

能否构思一个算法，在加载游戏或资源包时自动计算音符盒声音的循环点？

### 零、决定性前提：必须做包络拉平

衰减样本里找不到"首尾电平相同"的循环区。不拉平时循环内逐周期起伏 **15.49 dB**；拉平后 **0.03–0.15 dB**。

> 拉平在这里不是妥协而是正解：循环段就是要恒定振幅，衰减由 release 阶段重新施加。

### 一、算法七阶段

```
① 解码预处理 → ② f0 估计 → ③ 噪声底/可用区 → ④ 循环起点
                                              ↓
                    ⑦ 输出 ← ⑥ 拒绝判定 ← ⑤ 循环长度（核心）
```

**② f0 估计**：Hanning 窗 + 16× 零填充 FFT + 抛物线插值，实测误差 **0.0002%**

**③ 噪声底与可用区**
```
NF   = RMS(最后 60ms)
可用区 = { t : envelope(t) > NF × 10^(SNR_min/20) }，SNR_min = 20 dB
```

**④ 起点 a**：`a = 包络峰 + 2 个周期`（躲开起音瞬态，否则循环带弓毛噪声 → 机枪声）

**⑤ 循环长度（核心三步）**
```python
k   = floor((可用区末端 - a) / P)      # P = SR/f0，取最大可用周期数
L   = round(k * P)
L*  = argmax NCC(xf[a:a+W], xf[a+L':a+L'+W])，L' ∈ [L - P/2, L + P/2]
loop[i] = x[a+i] / envelope(a+i) × envelope(a)
```

### 二、四个反直觉结论

**1. 必须先拉平，再搜 L。** 顺序反了全盘皆输——同一份数据，未拉平 NCC 只有 0.917（选到 81ms）；先拉平 0.9918（选到 183.8ms）。**循环长度直接翻倍。**

**2. NCC 搜索范围必须约束在 ±半周期**（最隐蔽的坑）

| 搜索范围 | 修正量 | 接缝跳变 |
|---|---|---|
| ±3%（无约束） | -231（跳到相邻 k） | 3.6× |
| **±半周期** | **+8（正好补偿误差）** | **0.7×** |
| ±6 样本 | +6（不够） | 4.5× |

**3. 微重采样基本无用。** 整数 L 的相位残差上限 0.5 样本 = **0.5× 平均样本间跳变**，亚样本级不可闻。只作兜底。

**4. 一套循环点通吃全部 25 个音高。** `AL_PITCH` 是整体重采样，"L 样本 = k 周期"任何速率下成立。实测 0.5×/1.0×/2.0× 起伏均 ≤ 0.05 dB。

### 三、算法性能

| 指标 | 朴素方案 | 本算法 |
|---|---|---|
| 长音包络起伏 | 9.37 dB | **0.01 dB** |
| 循环率残余调制 | -13.30 dBc | **-86.23 dBc** |
| 接缝跳变 | 18.2× | **0.7×** |

### 四、鲁棒性

| 样本条件 | 选出的 L | 相关度 | 包络起伏 |
|---|---|---|---|
| 理想纯谐波 | 183.8 ms (k=34) | 0.992 | 0.22 dB |
| 轻微非谐性 B=2e-5 | 102.7 ms | 0.981 | 1.44 dB |
| 强非谐性 B=2e-4 | 48.5 ms | 0.953 | 0.19 dB |
| 颤音 ±8 cents | 200.0 ms | 0.991 | 0.21 dB |
| 颤音 ±25 cents | 200.0 ms | 0.991 | 0.19 dB |
| 高噪声底 1% | 113.5 ms | 0.990 | 0.17 dB |
| 极快衰减 tau=40ms | 81.1 ms | 0.970 | 0.17 dB |
| **极短样本 0.25s** | — | — | **拒绝** |

非谐性和噪声会让算法**自动缩短 L** 保住接缝——退化方向正确。

### 五、MC 集成要点

- **何时算**：懒加载，Mixin `SoundEngine#play`，首次遇到才分析，存 `Map<ResourceLocation, LoopPoints>`，16 个乐器总计 < 100ms
- **拿 PCM**：从 `ResourceManager` 自己解码，别从 OpenAL buffer 读回
- **设置循环点**：`ALC_SOFT_loop_points` + `alBufferiv`（单位样本，正好对上分析域）
- **无扩展兜底**：预渲染 `attack + N×loop` 成新 buffer（8 秒 ≈ 1.4MB/乐器 × 16 ≈ 22MB）

### 六、边界

- 只适用于有准周期性的样本，打击乐/噪声类应直接跳过
- 拉平会放大尾端噪声，SNR_min=20 dB 不能放松
- 同音反复被合并逻辑吃掉，需独立配置 W

## 第 5 轮｜综合可行性总结

### 提问

总结并综合讨论可行性

### 一、根因链条

```
音符盒只有固定采样，无 sustain
  → 长音只能靠 1gt 重触发拼接
    → ① 衰减尾巴被下一个音顶起 → 20 Hz 锯齿
    → ② 每次从相位 0 重启 → 相位步进 → 几 Hz 慢周期
```

**所有直觉方案都被数据否掉**：

| 直觉做法 | 实测 | 判定 |
|---|---|---|
| 加软起音、去弓毛噪声 | 改善 -1.09 dB | 无效 |
| 拉大间隔到 2gt/3gt | -12.81 / -11.48 dBc | **反效果** |
| 单纯缩短样本 | 起伏飙到 28 dB | 更糟 |
| Sound Physics 加混响 | 只加尾巴 | 无关 |

### 二、三层方案栈

| 层 | 工作量 | 风险 | 独立价值 |
|---|---|---|---|
| L0 样本改造（60ms 平台 + sin² 淡化 8ms） | 几小时 | 无 | -19.56 → **-56.65 dBc** |
| L1 合并 voice | 2–3 天 | 中 | 验证核心假设 |
| L2a 资源包 loop 规范 | 1–2 天 | 低 | 简单可靠 |
| **L2b 自动循环点** | **1–2 周** | **高** | 通用性 |

### 三、真正的风险（按杀伤力）

**★ Vorbis 是有损编码** — 最大未验证项
**★ 真实采样的复杂度** — 混响尾巴、多层叠加、非谐性
**★ L1 会吃掉同音反复** — 硬限制，无力度信息

其余：`ALC_SOFT_loop_points` 可用性、高音区循环速率 10.88 Hz 落在听觉敏感频段、Ogg 解码不能干扰 MC 加载

### 四、兼容性

| 现有方案 | 关系 |
|---|---|
| **Notica** | 最佳挂载点，建议 fork |
| **Extended Note Block** | 服务端侧，与本方案（客户端播放侧）互补 |
| **Sound Physics Remastered** | 正交可共存 |
| **Audio Improvements** | 与 Sound Physics 已知冲突 |

### 五、建议路径

**先做 L0 和 L1，再决定要不要投入 L2b。**

L0 是零代码方案，实测 -56.65 dBc，可能已经解决问题。写模组的真正价值是**通用性**——让任意资源包开箱即用。

## 第 6 轮｜游戏内实践路径

### 提问

想要在游戏中运行红石电路播放 1gt 的连续长音，听感更好，要怎么做？

### 一、先纠正方向：保持 1gt，别改

对衰减型样本，**触发越密越平滑**：

| 间隔 | 调制深度 |
|---|---|
| **1gt** | **-19.80 dBc** |
| 2gt | -12.81 dBc |
| 3gt | -11.48 dBc |

**1gt 已是最优间隔，别动它。要改的是样本，不是电路。**

### 二、首选方案：改样本（零代码，收益最大）

```
有效长度 = 60 ms        (= 1gt 50ms + 10ms 交叠)
包络     = 中间平坦，不衰减
首尾     = 各 8 ms，sin² (等功率) 淡化
```

**两个关键认知**
1. 要的是"不衰减的平台"，不是"更短的样本"
2. 平台长度必须匹配间隔（60ms 配 50ms = 1.2 层重叠）

**附带性能收益**：250ms 尾巴 @1gt = 每声部 5 个声音并发；60ms = 1.2 个。MC 声音引擎约 256 并发上限，改成 60ms 后并发降到 1/4，**丢音和卡顿明显改善**。

### 三、更彻底：干脆不重触发

- **做法 A：双音色分轨**（推荐）— 16 个乐器槽分设断奏短音与延音型长音（0.5–2 秒平台）
- **做法 B：Extended Note Block** — `sustain` 参数一次触发出精确长度

### 四、听音环境与工程设置

- **站着别动** — 音符位置钳到整数坐标，移动时声像跳变
- **距离 10–20 格** — 站在声源阵列中心
- **单声道 44.1 kHz** — 点声源做 3D 定位，立体声可能被意外下混
- **Ogg 码率 ≥ 192 kbps** — 低码率 Vorbis pre-echo 糊掉瞬态
- **首尾采样值接近 0，去 DC offset** — 重新编码后复查

### 五、客户端增强（优先级低）

- **Notica** — 播 .nbs 文件，对实时红石电路不适用
- **Sound Physics Remastered** — 轻混响能涂抹部分 20 Hz 调制，但密集时 CPU 开销实在
- **Audio Improvements** — 与 Sound Physics 冲突

### 六、一小时检查清单

1. 压成平台包络，裁到 **60 ms**
2. 首尾 **8 ms sin² 淡化**
3. 首尾采样值接近 0，去 DC；重编码后复查
4. 整轨降 **3–6 dB**
5. 固定位置录干声，拖进 Audacity 看包络
6. 分别听 **F#3 和 F#5**

> **判据**：50ms 锯齿消失就到此为止。还看得到再考虑 Extended Note Block 或写模组。
>
> 最容易犯的错：花两周写模组去解决一个改 10 分钟样本就能解决 90% 的问题。

## 第 7 轮｜L2b 实现（循环点检测工具）

### 提问

我对 L2b 比较感兴趣

### 一、关键结论：Vorbis 有损不是问题

三种码率各跑 11 个样本：

| Vorbis 质量 | 约合码率 | 通过率 |
|---|---|---|
| q3 | ~112 kbps | **9/11** |
| q6 | ~192 kbps | **9/11** |
| q10 | ~500 kbps | **9/11** |

最低码率 NCC 仍有 0.9980。两个稳定被拒的**都是应该被拒**的：强非谐性（无固定周期）、打击乐（无基频）。

### 二、过程中纠出的三个 bug

**① NCC 不是接缝的充分判据**（原设计最大漏洞）

| NCC 阈值 | 颤音 8c 接缝 | 颤音 25c 接缝 |
|---|---|---|
| 0.90 | 16.2× | 20.5× |
| 0.95 | 13.7× | 15.6× |
| 0.99 | 2.9× | 7.6× |
| 0.999 | 1.3× | 1.7× |

NCC 允许几个样本的相位漂移——60ms 窗口相关性还是 0.95，但漂移到接缝处正好变成咔哒。提高阈值能解决，代价是大量误拒。

**真正的解法：循环点交叉淡化**（采样器标准做法）

把尾部 X 毫秒混入头部，使 `out[0] = src[L]` 与 `out[-1] = src[L-1]` 天然相邻：

| | 无淡化 | 5ms 淡化 |
|---|---|---|
| 颤音 8c | **13.6×** | **1.2×** |
| 颤音 25c | **15.6×** | **0.0×** |
| 引入的音色伪影 | — | 仅 0.24 dB |

这样 NCC 阈值可放心留在 0.95。

**② 噪声底估计全线误判**

用"尾部 60ms RMS"当噪声底，在**包括理想样本在内的所有案例**上都是绝对阈值占优——衰减型样本的尾部还是乐音。改成**尾端平台检测**（尾部走平才算噪声底，仍在衰减就判为信号），慢衰减样本从"拒绝"变成 NCC 0.9999 PASS。

**③ 接缝度量本身是错的**

掺入淡化区后整体 `mean|diff|` 被拉小，比值虚高，本已平滑的接缝（真实 0.9×）被报成 4.3×。改用**端点局部差分**后，三种码率统一稳定在 9/11。

### 三、最终性能（q6）

- 长音（1 秒）包络起伏 **0.00–0.09 dB**
- 循环率残余调制 **-56 到 -92 dBc**
- 接缝 **0.0–2.0×**（<3 无咔哒）
- 音高 0.5× / 1.0× / 2.0× 验证均 ≤ 0.26 dB

对比朴素方案的 9.37 dB 起伏、-13.30 dBc 调制、18.2× 接缝。

### 四、工具用法

```bash
python loopdetect.py 音色.ogg                     # 分析
python loopdetect.py 音色.ogg --render 试听.wav    # 渲染长音试听
python loopdetect.py 资源包/ --batch --json        # 批量，输出循环点
```

参数：`--snr`、`--ncc-min`、`--xfade`、`--dynrange`、`--pitch`、`--total`

输出 `attackEnd / loopStart / loopEnd`（44.1kHz 样本单位），正好是 `ALC_SOFT_loop_points` 需要的格式。判定 PASS / WARN / FAIL 三档。
